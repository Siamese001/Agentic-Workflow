PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
C0.1.1 Receive and freeze inputs
- Accept query_spec and RouteContract exactly as handed off.
- Bind request_id, route_id, replay_key, policy_hash, blueprint_hash, and support_target.
- Refuse implicit source expansion from user text or retrieved-looking content.
- Emit input_freeze_receipt.

C0.1.2 Classify support need
- Determine whether the task needs quote, summary, policy clause, code location, incident evidence, RCA, comparison, or claim check.
- Derive evidence standard from support_target.
- Set dense/sparse/metadata/graph requirements.
- Emit support_target_profile.

C0.1.3 Select source classes
- Include only source classes allowed by RouteContract and L5 scope.
- Apply tenant, ACL, region, data class, and freshness ceilings.
- Record excluded source classes and reasons.
- Emit source_class_decision_report.

C0.1.4 Choose retrieval lanes
- Enable dense for semantic recall where useful.
- Enable sparse when exactness matters.
- Enable metadata filters for source/version/scope control.
- Enable cache only as candidate context under reuse-safe policy.
- Enable trace/code lanes only when support_target requires them and route permits them.
- Enable graph_seed when C0.3 may need anchors.

C0.1.5 Allocate budgets
- Split latency, tokens, top_k, parent expansion, child expansion, graph hops, and refine attempts across lanes.
- Reserve budget for C0.4 shaping and C0.5 contract verification.
- Reserve refinement budget only when L0 explicitly grants max_refine_attempts > 0.
- Emit budget_allocation_report.

C0.1.6 Emit deterministic plan
- Normalize field order.
- Hash stable fields.
- Emit plan_manifest_hash and replay_metadata.
- Handoff to C0.2.
