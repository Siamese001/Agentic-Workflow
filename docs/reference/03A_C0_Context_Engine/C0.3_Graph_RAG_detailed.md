C0.3 GRAPH TRAVERSE / GREEN MAPS
======================================================================================================================================================

OBJECTIVE

Implement C0.3 Graph Traverse as a read-only graph expansion stage inside the C0 Context Engine.

C0.3 receives hydrated candidate evidence from C0.2A and emits GraphExpandedEvidencePool for C0.4 Shape / Rerank / Stratify.

C0.3 must add graph-derived evidence context:
- definitions
- source lineage
- owners
- dependencies
- implementation links
- runtime observations
- contradictions
- supersession / stale-source signals
- rejected neighbors with reasons
- traversal manifest for replay and observability

C0.3 must not answer the user.
C0.3 must not route.
C0.3 must not execute tools.
C0.3 must not mutate L4.
C0.3 must not approve, deny, commit, or escalate.
C0.3 must not promote durable memory.
C0.3 must not bypass Prompt Assembly.
C0.3 emits evidence only.

The parent file states:
- C0 retrieves, expands, shapes, verifies, scores, and contracts evidence for downstream Prompt Assembly.

3.4 build_traversal_plan
------------------------------------------------------------------------------------------------

Map support_target to relation policy.

Support target policies:

EXACT_QUOTE:
- allowed: parent/section, source_version, supersedes, duplicates
- avoid: broad dependency walks
- max_hops recommended: 1

SOURCE_SUMMARY:
- allowed: references, defines, parent/child, supersedes, contradicts
- max_hops recommended: 1-2

POLICY_CLAUSE:
- allowed: governed_by, supersedes, contradicts, source_version
- require freshness/version scan
- max_hops recommended: 1-2

CODE_LOCATION:
- allowed: defines, imports, calls, implements, tested_by if available
- max_hops recommended: 1-2

INCIDENT_EVIDENCE:
- allowed: observed_in, triggered_by, remediated_by, trace, deployment, ticket
- require time-window filtering

ROOT_CAUSE_RANKING:
- allowed: depends_on, depended_on_by, calls, observed_in, remediated_by, contradicts
- require contradiction scan

COMPARISON:
- require symmetric expansion for both compared items
- avoid biased expansion depth

CLAIM_CHECK:
- allowed: direct support, contradicts, supersedes, source_authority
- require contradiction scan

ARCHITECTURE_BOUNDARY:
- allowed: owns, depends_on, governed_by, violates, implements, calls
- require boundary/scope filtering

BLAST_RADIUS:
- allowed: depends_on, depended_on_by, imports, calls
- require max_hops and max_nodes hard limits

GOVERNANCE_DECISION:
- allowed: governed_by, approved_by, requires, prohibits, exception_to, evidence
- avoid implementation-only proof without policy support

The plan must be deterministic:
- same input + same graph manifest + same policy_hash produces same traversal plan

3.5 bounded_graph_walk
------------------------------------------------------------------------------------------------

Rules:
- traversal starts only from resolved anchors
- enforce max_hops
- enforce max_nodes
- enforce max_edges
- enforce max_neighbors_by_anchor
- enforce allowed_relation_types
- enforce disallowed_relation_types
- detect cycles
- preserve relation_path
- collect accepted, rejected, contradiction, supersession, dependency, lineage, ownership, implementation, and runtime candidates
- stop branch on ACL failure
- stop branch on stale projection when required
- stop branch on support relevance failure
- never continue traversal through a rejected node unless relation policy explicitly allows looking for contradiction/supersession metadata

- projection builder reads SQLite to build GraphDB projection
- CI checks read SQLite baselines
- replay harness may verify SQLite snapshot metadata
