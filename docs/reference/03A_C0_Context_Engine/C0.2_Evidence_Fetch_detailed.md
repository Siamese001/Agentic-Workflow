PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
C0.2.1 Validate plan
- Confirm plan was emitted by C0.1.
- Confirm lane list, budgets, source classes, and filters are explicit.
- Confirm C0.2 is not being asked to choose sources or routes.

C0.2.2 Execute dense lane
- Convert query text to query_vec only if C0.1 enabled dense lane.
- Search dense fact/context vectors.
- Preserve embedding model id, vector dimension, collection id, snapshot id, and query vector digest.
- Do not use dense score as final truth.

C0.2.3 Execute sparse/BM25 lane
- Search exact terms, paths, symbols, IDs, dates, versions, policy labels, and clause text.
- Preserve tokenization profile, analyzer version, corpus snapshot, and term-match evidence.
- Required for exact support targets.

C0.2.4 Execute metadata lane
- Apply tenant, region, data class, source type, author, version, time, and environment filters.
- Prevent wrong-scope hits from entering the pool even when semantic score is high.
- Emit filter_report.

C0.2.5 Execute cache candidate lane
- Read cache only when C0.1 plan allows it.
- Treat cache as candidate context with original lineage, not as answer authority.
- Reject cache entries missing support lineage.

C0.2.6 Execute trace/code/table/ticket lanes
- Use adapters only when explicit in RetrievalPlan.
- Preserve exact source handles: trace_id, span_id, file path, symbol, row key, ticket id, incident id.
- Attach timestamp ranges and snapshot refs.

C0.2.7 Hydrate candidates
- Expand parent/child context only within max_parent_expansion and max_child_expansion.
- Attach citation anchors where available.
- Extract entities, symbols, dates, IDs for C0.3 graph anchors.
- Apply origin labels and content hashes.
- Do not sanitize by deleting evidence; mark unsafe or instruction-like payloads for C0.4/C0.5 handling.

C0.2.8 Emit CandidateEvidencePool
- Preserve lane provenance.
- Preserve lane errors and timeouts as evidence gaps.
- Hash pool manifest deterministically.
- Handoff to C0.3 if graph is enabled, otherwise C0.4.
