| **1** | **Structural** | **Layering Model** | **1x** | **Monolithic Script:** Single file or large loop handling prompts, tool calls, and parsing. No distinction between "planning" (cognitive) and "doing" (action). | **2** | **Structural** | **Agent Boundaries** | **1x** | **God Agents:** One agent has access to all tools (SQL, Email, Slack) and broad system prompts. Context bleeds between distinct tasks (e.g., a coding agent knowing about HR policies), polluting the reasoning window. | **Loose Personas:** Agents are defined by role (e.g., "Researcher", "Writer"), but permissions often overlap. Shared history pollutes context windows, leading to confusion. | **Collaborative Ecosystem:** Principles of Least Privilege applied to **Micro-Agent Swarms**. | **3** | **Structural** | **Typed Contracts** | **2x** | **String Soup:** Components pass raw natural language strings. Downstream functions rely on regex or fuzzy matching to parse outputs. Frequent `AttributeError` or parsing failures occur on edge cases or unexpected model verbosity. | **Partial Structure:** Key outputs use JSON mode to structure data, but inputs remain freeform strings. Validation is often handled via `try/catch` blocks rather than strict schema enforcement. Internal flows still rely on "magic strings." | **Strict Schemas (Pydantic/MCP):** Every node entry/exit is governed by versioned schemas. [cite_start]Integration via **Model Context Protocol (MCP)** guarantees data integrity[cite: 285]. **Type-safe parsing** ensures compile-time checks for agent interactions. |
| **4** | **Structural** | **Workflow (DAGs)** | **1x** | **Linear Scripts:** Execution follows `Step A -> Step B -> Step C`. If B fails, the whole process dies. Logic flows are hardcoded in Python `if/else` statements. The process is impossible to visualize or pause/resume. | **Hardcoded Retries:** Loops exist for specific failures (e.g., "retry 3 times"), but the graph logic is buried in code. Limited observability into which branch was taken. State is often transient and lost on crash. | [cite_start]**Think-Act-Observe Loop:** Workflows model the **5-step cycle** (Mission, Scene, Think, Act, Observe) [cite: 108-121]. Dynamic DAGs support conditional branching, sub-graphs, and state persistence, allowing for pause, resume, and human intervention. |
| **5** | **Behavioral** | **Capability Maturity** | **1x** | **Brittle Execution:** Happy-path only. Unexpected API responses or model hallucinations cause unhandled exceptions. Debugging requires reading raw text logs. Agents fail silently or catastrophically. | **Reactive Fixes:** Code handles known errors (e.g., JSON decode error). Agents can self-correct simple formatting issues but often get stuck in loops on logic errors. Relies on humans to diagnose complex failures. | **Self-Evolving / Agent Gym:** Autonomic "Immune System" monitors health. [cite_start]Agents use an **Agent Gym** for offline simulation and training [cite: 746-750]. [cite_start]The system can **dynamically create new tools** or sub-agents to fill identified capability gaps[cite: 222]. |
| **6** | **Behavioral** | **Reasoning Models** | **2x** | **Shotgun:** Single prompt, immediate answer. No "thinking" time allocated. Complex tasks fail because the model rushes to generation without planning or self-correction. | **Implicit CoT:** "Let's think step by step" added to prompts. Improvement seen, but reasoning is unstructured and often conflated with the final output format. Consistency varies across tasks. | [cite_start]**Structured Reasoning:** Systematic use of **Chain-of-Thought**, **Tree-of-Thought**, or **ReAct**[cite: 70]. Reasoning traces (The "Think" step) are separated from final Actions. Tool-augmented reasoning is tuned per specific task complexity. |
| **7** | **Behavioral** | **Context Engineering** | **1x** | **Infinite Scroll:** Appending all history until `ContextWindowExceededError`. Critical instructions get pushed out of the attention window by irrelevant chat noise or long tool outputs. | **FIFO/Summary:** Rolling window (First-In-First-Out) or naive summarization of past turns. Loss of specific details (e.g., variable values) over long conversations. Context is static and unmanaged. | [cite_start]**Context Curation:** Active **Context Engineering**[cite: 82, 193]. [cite_start]The system acts as the ultimate curator[cite: 61], dynamically pinning core instructions and swapping context slots based on retrieval (RAG) and relevance to the current step. |
| **8** | **Behavioral** | **Tool Ecosystem** | **2x** | **Direct Invocation:** Prompt output fed directly into `exec()` or API calls. No timeouts, validation, or error handling. Infinite loops are common if a tool fails or returns unexpected data. | **Basic Wrappers:** Tools have `try/except` blocks. Retries exist for network glitches. Output length is capped to prevent context flooding. Long-tail failures can still break flows. | **Resilience Middleware:** Circuit breakers, rate limiting, and backoff. [cite_start]**Hybrid Tooling** combines Native Function Calling [cite: 286] with Client-side Tools. Fallback strategies (e.g., Google -> Bing) trigger automatically on failure. |
| **9** | **Operational (Runtime)** | **Safety & Policy** | **2x** | **Suggestion Box:** "Please be nice" is the only safety control in the system prompt. No mechanisms to prevent PII leakage, injection attacks, or off-policy actions. | **Regex Filters:** Post-processing checks for banned words or basic patterns. Prompt engineering attempts to mitigate jailbreaks, but coverage is spotty and brittle. | [cite_start]**Control Plane & Hybrid Guardrails:** Centralized **Control Plane** [cite: 654, 662] [cite_start]enforcing **Defense-in-Depth** (Deterministic Rules + AI Guard Models)[cite: 555, 606]. Granular policies are applied to specific Agent Identities. |
| **10** | **Operational (Runtime)** | **Observability** | **2x** | **Console Logs:** Debugging via `print(response)`. No correlation between planning steps and final output. Blind to costs, latency, and token usage per step. | **Basic Tracing:** Logging inputs/outputs to a file or DB. Some visualization of the chain, but metadata (token counts, tool latency) is sparse and not fully correlated. | [cite_start]**Agent Ops:** Full tracing (e.g., OpenTelemetry) of the **Execution Trajectory**[cite: 472]. [cite_start]**LM-as-a-Judge** evaluates quality against golden datasets[cite: 452]. Alerts on error rate spikes or cost anomalies. |
| **11** | **Operational (Runtime)** | **Cost & Optimization** | **1x** | **Model Monoculture:** Using the most expensive model (e.g., GPT-4/Opus) for everything, even simple classifiers. Costs scale linearly with volume. No awareness of token spend. | **Static Tiers:** Manually coding "Use GPT-3.5 for summaries". Basic response caching prevents identical re-runs, but optimization is manual and infrequent. | [cite_start]**Dynamic Routing:** Optimization via **Model Routing** (Pro for reasoning, Flash for tasks)[cite: 250]. **Semantic Caching** (Redis/Vector) prevents redundant reasoning chains. Token budget enforcement per run. |
| **12** | **Operational (Lifecycle)** | **Testing (Golden State)** | **2x** | **Vibe Checks:** Manual testing in a playground. "Looks good." Regressions are discovered late by users. No systematic tracking of quality over time. | **Unit Tests:** Testing utility functions (e.g., "does the calculator work?"). Small set of prompt examples run manually before deploy. Limited coverage of edge cases. | [cite_start]**Semantic Eval Suite:** **Golden Datasets** covering breadth of use cases[cite: 456]. [cite_start]Automated **A/B Testing** of new agent versions against production baselines[cite: 469]. CI/CD blocks merges on regression. |
| **13** | **Operational (Lifecycle)** | **Prompt Governance** | **1x** | **Hardcoded Strings:** Prompts live inside Python files (`f"You are a {role}..."`). Changing a prompt requires a code deploy. No history of what changed or why. | **Config Files:** Prompts extracted to `.txt` or `.json`. Easier to edit, but versioning depends on git commit history. No collaborative editing, tagging, or formal review process. | **Prompt Registry (CMS):** Centralized Prompt Management System. Prompts treated as **Constitutional** assets.
