OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement the Exit checks that determine whether the sealed current run is reliable, replayable, and observable enough to
allow a response or request durable commit.

This child answers one question only:
"Is this run consistent, replay-certifiable, and observable enough for the selected disposition class?"

X1G CONSISTENCY MODIFIER pass^k
------------------------------------------------------------------------------------------------------------------------
Purpose:
- Apply commit-path reliability pressure to durable mutation candidates without confusing live runtime with offline analytics.

Scope:
- Hard runtime gate only for X3C commit request candidates.
- Advisory telemetry for X3D answer-only allow.
- Does not use pass@k as runtime gate.
- pass@k remains analytics for L6/capability-track hill-climb and future learning.

Checks:
- Identify trajectory_class from current run.
- Inspect recent same-class trajectories from sealed telemetry, not live mutable state.
- Compute recent k-trial reliability using policy-defined window.
- Require pass^k >= theta from X1A policy for active commit path.
- Customer-facing durable commits require high theta, e.g. .95 if policy says so.
- Internal reversible commits may use lower theta where policy allows.
- High-impact or irreversible actions may require theta plus HITL.
- Low sample size returns UNKNOWN, not fake pass.
- Drifted trajectory class invalidates old reliability.

Inputs:
- ExitReviewPacket
- trajectory_class
- track_label
- policy threshold profile
- sealed BUS T / route class reliability refs
- pass_power_config
- sample_quality rules

Outputs:
- consistency_status = PASS | FAIL | UNKNOWN | NOT_APPLICABLE
- trajectory_class
- k_window
- theta
- pass_power_estimate
- sample_quality
- consistency_reason_codes
- commit_path_blocker

Fail routes:
- CONSISTENCY_FAIL
- CONSISTENCY_UNKNOWN_FOR_HIGH_IMPACT
- TRAJECTORY_CLASS_DRIFT
- SAMPLE_TOO_SMALL_FOR_COMMIT
- RELIABILITY_PROFILE_MISSING

X1H REPLAY & DETERMINISM OK?
------------------------------------------------------------------------------------------------------------------------
Purpose:
- Verify the run can be reconstructed enough for the chosen risk class.

Checks:
- Same input + same envelope + same policy_hash + same read snapshot has stable digest.
- No decision depends on uncontrolled wall clock.
- No raw entropy, uuid4, nondeterministic IDs, unstable provider metadata, or mixed state reads affect decisions.
- Network calls were snapshotted, sealed, or explicitly outside replay-critical path.
- State reads came from one declared snapshot.
- Policy mismatch invalidates replay certification.
- Model/tool calls have replay receipts or declared non-replayable status.
- Timing offsets are recorded without affecting decisions.
- Prompt hash, route digest, evidence contract hash, sealed artifact hash, and exit packet hash are bound.
- Human review packet, if any, is versioned and replay-bound.
- PTC/script execution records deterministic command, env allowlist, cwd, stdout/stderr hash, and artifact hashes.

Outputs:
- determinism_status
- replay_digest
- snapshot_manifest_status
- nondeterminism_flags[]
- replay_gap_report
- replay_certification_level
- high_impact_replay_clearance

Fail routes:
- NON_REPLAYABLE
- HIDDEN_TIME
- RAW_ENTROPY
- MIXED_STATE_READS
- POLICY_MISMATCH
- SNAPSHOT_MISSING
- PROMPT_HASH_MISMATCH
- TOOL_RECEIPT_MISSING
- PTC_IO_UNTRANSCRIPTED

X1I OBSERVABILITY COMPLETE?
------------------------------------------------------------------------------------------------------------------------
Purpose:
- Verify trace/evidence coverage is sufficient for forensic review, L6 exhaust, and current-run disposition.

Checks:
- OTel trace_root exists.
- Spans cover L0/L3/L2/Exit/HITL/UWG where applicable.
- Tool/model/PTC invocation spans include provider/tool/script, latency, cost, retry, error metadata.
- Exit disposition span exists and has final X3 outcome.
- replay_key, policy_hash, blueprint_hash, route_id, and source_type appear in trace attributes.
- Evidence bundle, citation map, state diff, and artifact IDs are linkable.
- BUS D/E live bell signals consumed before disposition.
- BUS T telemetry exhaust sealed for future learning after disposition.
- No observability gap blocks forensic replay.
- Trace gap materiality is classified by risk class and commit path.

Outputs:
- trace_completeness_score
- span_coverage_map
- evidence_seal_status
- anomaly_flags[]
- live_bell_consumption_status
- forensic_replay_status
- observability_gap_report

Fail routes:
- TRACE_MISSING
- SPAN_COVERAGE_GAP
- EVIDENCE_SEAL_FAILED
- LIVE_BELL_SIGNAL_UNCONSUMED
- FORENSIC_REPLAY_BLOCKED
- ARTIFACT_LINK_BROKEN
- EXHAUST_NOT_SEALED

MATERIALITY MATRIX
------------------------------------------------------------------------------------------------------------------------
Answer-only low-risk:
- X1G NOT_APPLICABLE.
- X1H WARN may be allowed if policy permits and no safety/write path.
- X1I WARN may be allowed if trace gap is non-material.

Grounded answer:
- X1H must preserve evidence contract and prompt hash.
- X1I must link citation/evidence refs.
- Material evidence-seal gap blocks allow.

Commit path:
- X1G must PASS unless policy explicitly waives for a narrow reversible internal write.
- X1H must PASS.
- X1I must PASS or policy-allowed non-material WARN.
- Unknown on high-impact commit path escalates.

High-impact action:
- X1G PASS or X3B.
- X1H PASS or X3A/X3B.
- X1I PASS or X3B.
- HITL may be required by X2 aggregation.
