OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement the Exit-managed HITL review lifecycle for X3B.

This child answers one question only:
"When human review is required, how does Exit freeze the run, materialize the minimum bounded packet, capture human input as data, and force re-clearance before final disposition?"

HARD LAW
------------------------------------------------------------------------------------------------------------------------
- Human input is data, not sovereign authority.
- Human review cannot write to L4.
- Human review cannot bypass L5.
- Human review cannot widen scope without re-entry.
- Human modifications must be re-cleared before they affect final disposition.
- No durable write while packet is frozen.
- No additional retrieval unless REQUEST_MORE_EVIDENCE is selected and bounded C0 re-entry is allowed.

H1 FREEZE
------------------------------------------------------------------------------------------------------------------------
On X3B selection:
- auth_state = FROZEN
- write_auth = NONE
- capability_token suspended or narrowed to review-only
- pending diffs locked
- provider egress paused
- external action paused
- mutation proposals made immutable
- review packet snapshot fixed
- trace/span records marked under_review
- no durable write while under review

H3 HUMAN REVIEW
------------------------------------------------------------------------------------------------------------------------
Human may:
- inspect evidence, action, replay, and diff.
- approve the proposed output/action subject to re-clearance.
- reject.
- modify output/diff.
- request more evidence.
- request replay.
- request schema repair.
- return to L1 for replan.

Human may not:
- write L4.
- override policy.
- widen scope silently.
- approve hidden side effect.
- turn untrusted content into authority.
- bypass L5 re-clearance.
- force unsupported factual claims.
- clear direct write attempts.

H4 DECISION ROUTING
------------------------------------------------------------------------------------------------------------------------
APPROVE:
- create L5 reclearance request.
- re-run X1A/X1C/X1F at minimum.
- if answer/evidence changed, re-run X1D.
- if process/tool plan changed, re-run X1E.
- if commit path active, re-run X1G/X1J.
- then aggregate via X2 again.

MODIFY_DIFF:
- capture HumanModificationDiff.
- mark modified text/diff as human_review_data.
- send to L5 re-clearance.
- re-run relevant X1 gates.
- no direct response before re-clearance.

REJECT:
- proceed to X3A DENY/STOP or RETURN_TO_L1 as appropriate.
- no durable write.

RETURN_TO_L1:
- emit bounded replan packet with reason codes.
- do not mutate L4.
- original run disposition remains X3B/X3A depending policy.

REQUEST_MORE_EVIDENCE:
- bounded C0 re-entry only if route policy permits.
- no general open loop.
- C0 returns evidence contract, not answer.
- re-run X1D and relevant gates.

REQUEST_REPLAY:
- run replay check through replay surface, not ad hoc execution.
- return to X1H/X1I.

REQUEST_SCHEMA_REPAIR:
- bounded L2 repair only.
- return to X1B/X1C/X1H.
