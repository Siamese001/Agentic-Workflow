OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement L0.2 as the deterministic dispatcher.

L0.2 answers one question only:
"Which one governed route is allowed for this L1 plan and route candidate frame?"

It emits exactly one selected route into RouteContract. It does not perform the downstream work.

FIXED DECISION ORDER
------------------------------------------------------------------------------------------------------------------------

0. Invalid envelope / scope fail / unsafe request
   -> R5_FALLBACK [RET]

1. Exact reusable answer with valid freshness, policy, tenant, and support compatibility
   -> R1A_EXACT_CACHE [RET]

2. Reuse-safe semantic match with calibrated confidence and no freshness/source-specific obligation
   -> R1B_SEMANTIC_CACHE [RET]

3. High-risk, irreversible, or authority-ambiguous mutation
   -> HITL posture annotation plus route toward Exit/UWG path, usually R5 or R4/R3R4 with HITL requirement

4. Low-risk reversible action, one bounded action, args available
   -> R4_SINGLE_ACTION -> L2

5. Factual/document/code/policy answer requiring support
   -> R3_SIMPLE_GROUNDED_READ -> C0 -> Prompt Assembly -> L2

6. Multi-hop read/action with dependencies or changing step contract
   -> R3R4_MANAGED_WORKFLOW -> L3 -> L2 step loop

7. No safe, grounded, reusable, or executable path
   -> R5_FALLBACK [RET]

ROUTE SELECTION RULES
------------------------------------------------------------------------------------------------------------------------

R1A exact cache is valid only when:
- normalized_request_hash matches.
- tenant_scope matches.
- policy_hash compatible.
- output schema compatible.
- freshness_class satisfied.
- source snapshot compatible.
- prior answer was not weak/conflicted/blocked.
- support obligations still satisfied.

R1B semantic cache is valid only when:
- semantic similarity is above calibrated threshold.
- task class is reuse-safe.
- no current/latest/fresh source requirement exists.
- no user-file or attached-doc obligation exists.
- no legal/medical/financial/regulatory high-stakes claim unless explicitly policy-approved.
- no action/mutation intent exists.
- tenant/policy/scope compatible.

R3 simple grounded read is valid when:
- factual, source, policy, code, contract, evidence-backed, file, connector, or currentness support is required.
- one bounded evidence pass and one bounded L2 synthesis step is enough.
- no dependency-changing workflow is needed.
- no action side effect is requested unless only argument grounding is needed for one action.

R4 single action is valid when:
- one reversible/low-risk action is requested.
- action arguments are complete or can be grounded in one C0 pass.
- capability and sandbox can be bound.
- no multi-step dependency state is required.
- durable write remains proposal-only until Exit/UWG.

R3R4 managed workflow is valid when:
- there are multiple dependent steps.
- step contract changes across steps.
- evidence must be gathered in stages.
- branch/join logic is required.
- parallel shards are safe and useful.
- HITL pause/resume or checkpoint/resume is required.
- bounded evaluator/optimizer loop is required.

R5 fallback is valid when:
- request is invalid, unsafe, vague, unsupported, blocked, out of scope, or too weakly supported.
- source access is missing and grounding is mandatory.
- tool/model unavailable with no safe substitute.
- budget exhausted before safe answer.
- cache confidence below threshold and C0 cannot be used.

PTC ROUTING RULE
------------------------------------------------------------------------------------------------------------------------
L0 may mark a selected R4 or R3R4 route as:
- ptc_execution_allowed = true
- ptc_requires_l2_sandbox = true
- ptc_requires_l5_certification = true
- ptc_raw_outputs_must_remain_isolated = true

L0 must not:
- generate the script as final authority.
- run the script.
- inspect raw tool outputs as if it were L2.
- bypass L2 sandbox or Exit.

DETERMINISM REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------

- No raw entropy.

- No mutable global defaults.
- Same RouteCandidateFrame + same policy_hash + same blueprint_hash + same snapshot_id -> same selected route.
- Route selection must be stable under dictionary/list ordering noise after canonicalization.
