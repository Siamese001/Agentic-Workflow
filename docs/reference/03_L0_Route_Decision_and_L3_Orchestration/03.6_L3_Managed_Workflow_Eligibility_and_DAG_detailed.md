OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement the L3 entry and graph builder for approved managed workflows.

L3.6 answers one question only:
"Given an approved MANAGED_WORKFLOW RouteContract, what bounded workflow graph or direct step package should L3 emit?"

L3.6 cannot change route_id. If the selected route is not R3R4_MANAGED_WORKFLOW, L3 must not run.

ENTRY LAW
------------------------------------------------------------------------------------------------------------------------
L3 may run only when:
- RouteContract.selected_route_id = R3R4_MANAGED_WORKFLOW
- RouteContract.execution_form = MANAGED_WORKFLOW
- workflow bounds are present
- policy_hash / blueprint_hash / replay_key present
- max_nodes, max_depth, max_iterations, SLO, fallback_chain present
- capability/sandbox requirements are present for action/tool/model steps

L3 must fail closed when:
- route identity is uncertain
- route contract missing
- L0 route_digest invalid
- policy_hash mismatch
- workflow bounds missing
- route attempts to let L3 decide a new route

PHASE 2 DAG BUILDER
------------------------------------------------------------------------------------------------------------------------

Required public entrypoint:

build_l3_workflow(input: L3WorkflowInput) -> ManagedWorkflowBlueprint

Steps:
1. validate_route_contract_is_managed
2. classify_execution_shape
3. extract_work_units_from_task_spec
4. build_nodes
5. build_edges
6. mark serial/parallel eligibility
7. assign C0/PA/L2/HITL step ownership
8. bind capability/sandbox requirements
9. bind retry/fallback/quality policies
10. emit WorkflowGraphManifest

DAG LAWS
------------------------------------------------------------------------------------------------------------------------
- Forward-only graph for current run.
- No backward graph edges.
- Feedback loops are bounded repeated node attempts, not retrograde authority edges.
- Every cycle-looking pattern must be represented as max_iterations over a controlled loop.
- Each node must have a single owner layer.
- C0 nodes request evidence only; L3 does not retrieve.
- L2 nodes execute only; L3 does not execute.
- PTC node is L2_PTC_SANDBOX_STEP only; L3 does not run script.

ACCEPTANCE TESTS
------------------------------------------------------------------------------------------------------------------------
- L3 refuses non-MANAGED_WORKFLOW RouteContract.
- Multi-hop task builds multiple nodes.
- Simple task does not become workflow without real dependency.
- PTC node is typed as L2_PTC_SANDBOX_STEP and not executed.
- DAG has no backward edges.
- Workflow graph hash is deterministic.
- Missing max_iterations fails closed.
