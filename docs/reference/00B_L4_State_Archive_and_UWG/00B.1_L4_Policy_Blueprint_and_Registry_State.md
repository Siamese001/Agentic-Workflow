PHASE 2 LOOKUP API REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
Implement read-only lookup functions or extend existing equivalents:
- get_active_policy_manifest(tenant_id, route_id, risk_tier, snapshot_id) -> PolicyManifest
- get_policy_by_hash(policy_hash) -> PolicyManifest
- get_blueprint_by_hash(blueprint_hash) -> BlueprintRecord
- get_registry_snapshot(registry_snapshot_id) -> RegistrySnapshot
- resolve_allowed_model_lane(model_id, provider_id, route_id, risk_tier, policy_hash) -> ModelRegistryRecord
- resolve_allowed_tool(tool_id, route_id, capability_id, policy_hash) -> ToolRegistryRecord
- resolve_schema(schema_id, schema_version, policy_hash) -> SchemaRegistryRecord

Rules:
- Reads must be tenant/ACL scoped.
- Reads must be point-in-time reconstructable.
- Unknown entries fail closed.
- Deprecated entries fail closed unless explicitly allowed by policy_hash and route snapshot.
- Alias records must resolve to immutable version records.
- No lookup may mutate alias state, cache state, memory state, or audit state.

PHASE 3 VERSIONING AND ALIAS RULES
------------------------------------------------------------------------------------------------------------------------
Required alias types:
- active
- previous
- next
- rollback_candidate
- canary_candidate
- retired

Rules:
- Active alias swap requires UWGCommitReceipt and AliasSwapReceipt.
- Policy alias swap without audit receipt is forbidden.
- Registry alias swap without registry_digest is forbidden.
- Blueprint alias swap without blueprint_hash is forbidden.
- In-place mutation is forbidden.
- All version changes insert new records and atomically swap aliases only after UWG commit.

PHASE 4 FAILURE MODES
------------------------------------------------------------------------------------------------------------------------
Fail closed when:
- policy_hash missing
- policy_hash stale
- blueprint_hash missing
- blueprint_hash stale
- registry_digest missing
- registry entry unknown
- registry entry deprecated and not explicitly allowed
- schema mismatch
- tenant overlay missing for tenant-specific request
- alias points to non-existent immutable record
- policy manifest has no audit refs
- registry snapshot cannot be reconstructed
- active policy differs from packet policy_hash and route forbids stale execution

PHASE 6 TEST REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
Tests must fail if:
- policy update happens without versioning
- registry update happens without registry_digest
- active alias swap happens without UWGCommitReceipt
- unknown tool/model/provider resolves as allowed
- deprecated registry entry resolves without explicit policy allowance
- policy lookup returns records outside tenant scope
- blueprint lookup returns a mutable object reference
- registry snapshot cannot reconstruct point-in-time allowed lanes
- L5 tries to commit policy state directly

ACCEPTANCE CRITERIA
------------------------------------------------------------------------------------------------------------------------
- All policy, blueprint, and registry records are immutable and versioned.
- Active aliases point to immutable records.
- Fail-closed behavior is implemented for unknown, stale, deprecated, or mismatched records.
- Registry snapshots expose deterministic digests.
- All reads emit OTEL and preserve replay identifiers.
