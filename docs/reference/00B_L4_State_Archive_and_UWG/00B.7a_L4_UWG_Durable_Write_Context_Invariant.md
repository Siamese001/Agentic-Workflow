OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Close the L4/UWG split-brain durable-truth gap by giving the durable
mutation pipeline a single typed artifact (DurableWriteContext) whose
deterministic digest must match across every stage from Exit CommitRequest
through retrieval/cache invalidation. Mismatch is fail-closed with a
sealed NO_DURABLE_MUTATION receipt and an UWG_COMMIT_BLOCKED disposition.

This file exists because, prior to its authoring, the 00B children each
defined their own surface (UWG admission, audit ledger, replay snapshot,
cache, retrieval, read-surface refresh) but no file owned the rule that
all stages must operate on the SAME mutation object. Five-way split-brain
is possible: UWG validates one object, the state store writes another,
the audit ledger records a third, the snapshot/replay indexes a fourth,
and the retrieval/cache surfaces expose a fifth.

CRITICAL BOUNDARY
------------------------------------------------------------------------------------------------------------------------
This is a DURABLE-WRITE binding invariant, not a Runtime Gate and not a
certification record. Mismatch produces a sealed NO_DURABLE_MUTATION
receipt, and UWG raises UWG_COMMIT_BLOCKED. Live ALLOW/DENY mechanics at
gates (00C) and Exit X3 (05) are unchanged. L5 certification evidence
(00A.7a) is composed alongside this invariant — both must hold.

PHASE 1 DATA CONTRACT — DurableWriteContext
------------------------------------------------------------------------------------------------------------------------
The DurableWriteContext is a frozen dataclass. Every required field
below the line is mandatory; optional fields are explicitly marked. The
canonical-JSON serialization sorts keys deterministically and is hashed
with SHA-256 to produce the durable_write_digest.

Identity fields (request- and tenant-scoped):
- request_id                       # opaque request id (frozen at intake)
- run_id                           # current-run id
- trace_id                         # OTEL trace id (root)
- tenant_id                        # tenant scope
- principal_id                     # resolved principal identity

Linkage fields (Exit ↔ UWG ↔ L4):
- exit_disposition_id              # X3 disposition that authorized this write
- commit_request_id                # Exit CommitRequest id
- uwg_receipt_id                   # UWG admission receipt id (frozen at admission)

Mutation surface (the binding):
- target_store_id                  # canonical id of the durable store
- target_object_ref                # canonical ref of the object being mutated
- mutation_intent_class             # CREATE|UPDATE|DELETE|UPSERT|TOMBSTONE
- state_diff_candidate_hash        # SHA-256 of the candidate state diff
- before_snapshot_hash             # SHA-256 of pre-mutation snapshot
- after_candidate_hash             # SHA-256 of post-mutation candidate
- schema_hash                      # SHA-256 of the target schema in scope

Authority surface (composed with L5 / L2):
- policy_hash                      # SHA-256 of resolved policy snapshot
- blueprint_hash                   # SHA-256 of resolved blueprint snapshot
- capability_scope_hash            # SHA-256 of resolved capability snapshot
- sandbox_envelope_hash            # SHA-256 of resolved sandbox envelope
- l5_certification_packet_hash     # SHA-256 of the L5 certification packet
                                   # (this is the AGGREGATE governance digest from 00A.7a;
                                   #  it MUST be present and L5_NOT_CERTIFIED writes
                                   #  MUST NOT reach this stage)

Idempotency / lock / transaction surface:
- replay_key                       # frozen replay key for exactly-once replay
- idempotency_key                  # frozen idempotency key for exactly-once commit
- write_lock_id                    # lock id held for this mutation
- transaction_id                   # transaction id for this mutation

Audit / replay / rollback surface:
- audit_manifest_hash              # SHA-256 of the audit manifest reference
- rollback_plan_hash               # SHA-256 of the rollback plan
- replay_snapshot_hash             # SHA-256 of the post-commit replay snapshot
- retrieval_invalidation_plan_hash # SHA-256 of the retrieval invalidation plan
- cache_invalidation_plan_hash     # SHA-256 of the cache invalidation plan
- read_surface_refresh_plan_hash   # SHA-256 of the read-surface refresh plan

Frozen-context surface:
- frozen_durable_write_context_hash # SHA-256 of the frozen 00B durable-write context
- uwg_resolver_digest               # digest of the UWG resolver implementation

PHASE 2 DIGEST RULE
------------------------------------------------------------------------------------------------------------------------
- Serialize the DurableWriteContext as canonical JSON (RFC 8785 / sort_keys=True,
  ensure_ascii=False, separators=(",", ":")).
- Compute SHA-256 over the UTF-8 byte representation.
- The hex digest is the durable_write_digest.
- Per-stage digests inherit named aliases:
    exit_commit_request_digest             (emitted by 05 Exit; consumed at UWG entry)
    uwg_validation_digest                  (emitted by 00B.6 UWG admission)
    write_lock_digest                      (emitted by lock manager inside 00B.6)
    commit_transaction_digest              (emitted by transaction manager inside 00B.6)
    l4_state_receipt_digest                (emitted by L4 state store on receipt)
    audit_ledger_digest                    (emitted by 00B.5 on append)
    replay_snapshot_digest                 (emitted by 00B.5 on snapshot index)
    retrieval_cache_invalidation_digest    (emitted by 00B.3 / 00B.4 / 00B.7 on invalidation/refresh)
- Bit-for-bit equality is the only acceptable comparison. Substring,
  prefix, and field-subset comparisons are FORBIDDEN.
- replay_key and idempotency_key are NEVER allowed to be re-derived by a
  downstream stage; they are frozen at Exit CommitRequest emission.

PHASE 3 EQUALITY CHAIN (cross-stage)
------------------------------------------------------------------------------------------------------------------------
For any durable mutation that reaches L4, the following MUST hold (in
emission order):

  exit_commit_request_digest             # 05 Exit emits
  == uwg_validation_digest                # 00B.6 UWG admits
  == write_lock_digest                    # lock manager binds
  == commit_transaction_digest            # txn manager binds
  == l4_state_receipt_digest              # L4 store confirms write
  == audit_ledger_digest                  # 00B.5 append confirms
  == replay_snapshot_digest               # 00B.5 snapshot confirms
  == retrieval_cache_invalidation_digest  # 00B.3/00B.4/00B.7 confirm

Any pairwise mismatch in the chain is a DURABLE_WRITE_CONTEXT_MISMATCH.
A missing digest at any stage (when the mutation reached that stage) is
also a mismatch (treated as first_mismatched_field = "<stage>_digest").

PHASE 4 INVARIANTS
------------------------------------------------------------------------------------------------------------------------
INV-DW-1   For any durable mutation that reaches L4, every stage digest
           in the equality chain MUST be identical.
INV-DW-2   The DurableWriteContext is frozen at Exit CommitRequest
           emission and SHALL NOT be mutated thereafter by UWG or any
           downstream stage.
INV-DW-3   No stage SHALL re-resolve mutation_intent_class,
           target_store_id, target_object_ref, schema_hash,
           state_diff_candidate_hash, before_snapshot_hash, or
           after_candidate_hash independently. Re-derivation that does
           not produce an identical hash is itself a mismatch.
INV-DW-4   Mismatch SHALL produce a sealed NO_DURABLE_MUTATION receipt
           with terminal_class = DURABLE_WRITE_CONTEXT_MISMATCH and
           decisive_rule_id = UWG_COMMIT_BLOCKED.
INV-DW-5   On mismatch UWG SHALL NOT call the L4 state store, SHALL NOT
           append to the audit ledger, SHALL NOT register a replay
           snapshot, and SHALL NOT trigger any cache or retrieval
           invalidation.
INV-DW-6   The sealed NO_DURABLE_MUTATION receipt SHALL include every
           emitted stage digest, the first mismatched stage name, the
           trace_id, and the replay/idempotency keys sufficient for
           Exit/L6 to reproduce the rejection.
INV-DW-7   l5_certification_packet_hash MUST be present and MUST equal
           the aggregate_governance_digest from 00A.7a. UWG SHALL NOT
           admit a write whose L5 certification is absent or whose
           aggregate_governance_digest does not match.
INV-DW-8   replay_key and idempotency_key SHALL be honored exactly once
           across the whole equality chain. A second admission with the
           same idempotency_key SHALL be a deduplicated no-op that emits
           the original l4_state_receipt_digest, not a fresh write.
INV-DW-9   capability_scope_hash, sandbox_envelope_hash, policy_hash,
           and blueprint_hash SHALL NOT be widened by any downstream
           stage. Widening is itself a mismatch.
INV-DW-10  audit_ledger_digest, replay_snapshot_digest, and
           retrieval_cache_invalidation_digest SHALL NOT be emitted
           before l4_state_receipt_digest. Out-of-order emission is a
           mismatch.

PHASE 6 SEALED NO_DURABLE_MUTATION RECEIPT
------------------------------------------------------------------------------------------------------------------------
On INV-DW-1 or INV-DW-2 violation, the chain emits a NoDurableMutationReceipt:
  - terminal_stamp = DURABLE_WRITE_CONTEXT_MISMATCH
  - decisive_rule_id = UWG_COMMIT_BLOCKED
  - decisive_reason = "<stage>_digest != <stage>_digest" (first mismatch)
  - committed = false
  - dispatch_target = EXIT_CONTROL
  - participating_digests = { exit_commit_request_digest, uwg_validation_digest,
        write_lock_digest, commit_transaction_digest, l4_state_receipt_digest,
        audit_ledger_digest, replay_snapshot_digest,
        retrieval_cache_invalidation_digest }
  - first_mismatched_stage, trace_id, sealed_receipt_id all sealed into the
    receipt body.
  - rollback_required = true if any stage past commit_transaction_digest
    emitted before the mismatch was detected; otherwise false.
