PHASE 2 CACHE COMPATIBILITY RULES
------------------------------------------------------------------------------------------------------------------------
A cache read is compatible only if:
- tenant_scope matches
- policy_hash is compatible
- blueprint_hash is compatible where required
- output schema is compatible
- source_snapshot refs remain valid for grounded answers
- freshness_class is satisfied
- semantic similarity clears calibrated threshold for semantic cache
- task class is reuse-safe
- answer was not previously weak/conflicted unless policy allows caveated reuse
- evidence lineage exists for grounded answers

Cache read is incompatible if:
- task asks for latest/current/live facts
- attached-file/source-specific obligation exists and cache source snapshot differs
- legal/medical/financial/regulatory/high-impact factual answer lacks strict evidence lineage
- user asks for exact quote and cached evidence lacks stable citation anchor
- policy drift occurred
- tenant boundary differs
- cache entry lacks evidence_contract_ref for grounded route

PHASE 3 READ APIs
------------------------------------------------------------------------------------------------------------------------
Implement read-only APIs or extend existing equivalents:
- lookup_exact_cache(normalized_request_hash, tenant_scope, policy_hash, freshness_class) -> CacheLookupReceipt
- lookup_semantic_cache(query_embedding_ref, task_class, tenant_scope, policy_hash) -> CacheLookupReceipt
- resolve_cache_entry(cache_entry_id, tenant_scope, snapshot_id) -> CacheEntry
- list_cache_invalidations(source_ref, policy_hash, snapshot_id) -> list[CacheInvalidationReceipt]

Rules:
- Lookup may return compatibility hints, not route decisions.
- L0 decides route based on RouteContract rules.
- Cache lookup must not execute model generation.
- Cache lookup must not promote cache entries.
- Cache lookup must not update access counters durably outside UWG. If counters exist, they must be append-only telemetry, not state mutation.

PHASE 4 CACHE MUTATION RULES
------------------------------------------------------------------------------------------------------------------------
Allowed cache StateDiff operation types:
- append_record
- cache_invalidate
- tombstone
- rollback

Forbidden:
- direct cache promotion from L2
- direct cache promotion from Prompt Assembly
- direct cache promotion from C0
- direct cache promotion from L6 raw telemetry
- cache entry without policy_hash
- cache entry without tenant_scope
- grounded cache entry without evidence_contract_ref
- semantic cache entry without embedding_model_id/version
- cache reuse across tenant or policy drift

PHASE 5 FAILURE MODES
------------------------------------------------------------------------------------------------------------------------

- cache entry lacks policy_hash compatibility

- source snapshot stale
- semantic threshold missing
- semantic embedding model version mismatch
- task class not reuse-safe

- cache invalidation ledger unavailable
- cache entry created by non-UWG surface
- exact cache request hash mismatch
