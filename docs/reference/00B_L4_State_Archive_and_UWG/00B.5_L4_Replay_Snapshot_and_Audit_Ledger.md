PHASE 2 REPLAY RECONSTRUCTION RULES
------------------------------------------------------------------------------------------------------------------------
Replay snapshot must support:
- point-in-time policy reconstruction
- point-in-time blueprint reconstruction
- point-in-time registry reconstruction
- route digest reconstruction
- prompt/evidence contract reconstruction where applicable
- gate verdict reconstruction
- exit disposition reconstruction
- commit request reconstruction
- StateDiff reconstruction
- before/after L4 snapshot reconstruction
- rollback target reconstruction

Stable hash inputs:
- normalized_request_hash
- input_hash
- prompt_hash
- route_digest
- evidence_contract_hash
- policy_hash
- blueprint_hash
- registry_digest
- sealed artifact hash
- gate verdict hashes
- exit disposition hash
- commit receipt hash

Forbidden as deterministic digest inputs:
- wall clock without run-clock policy
- raw entropy
- hidden provider state
- mixed-state reads
- non-versioned external API response
- mutable object addresses
- unsorted JSON
- non-canonical path aliases

PHASE 3 AUDIT LEDGER RULES
------------------------------------------------------------------------------------------------------------------------
Audit ledger is append-only.

Required event types:
- commit_request_received
- commit_validated
- commit_blocked
- write_lock_acquired
- write_lock_failed
- atomic_commit_applied
- rollback_applied
- alias_swap_applied
- registry_snapshot_published
- policy_version_published
- memory_promotion_committed
- cache_invalidated
- index_refresh_started
- index_refresh_completed
- graph_projection_refreshed
- read_surface_refresh_completed
- direct_write_attempt_blocked

Rules:
- Audit ledger record must be written for every UWG commit/blocked/rollback path.
- Ledger entries must not be overwritten or deleted.
- Correction uses append_record with supersedes_ref, not mutation.
- Ledger unavailable means commit fails closed.
- Audit append failure after commit must trigger incident evidence and rollback policy if configured.

PHASE 4 FAILURE MODES
------------------------------------------------------------------------------------------------------------------------
Fail closed when:
- replay key missing
- snapshot manifest missing
- audit ledger unavailable
- deterministic digest mismatch
- replay snapshot cannot reconstruct committed state
- environment digest missing for replay-required route
- audit ledger sequence gap detected
- receipt chain incomplete
- rollback lacks before_snapshot
- commit receipt hash mismatch
- gate verdict hashes missing for gate-required commit
- source snapshot stale for retrieval-linked commit

PHASE 6 TEST REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
Tests must fail if:
- replay snapshot cannot reconstruct committed state
- commit applies without audit ledger append
- rollback lacks before_snapshot
- deterministic digest changes across identical canonical input
- replay digest includes wall-clock value without clock policy
- audit ledger entry is overwritten
- audit ledger sequence gap is ignored
- commit receipt hash is missing from replay snapshot
- policy/registry alias swap lacks audit record
- direct file/DB write path bypasses audit ledger

ACCEPTANCE CRITERIA
------------------------------------------------------------------------------------------------------------------------
- Every committed mutation can be reconstructed from replay and audit state.
- Audit ledger is append-only and sequence-checked.
- Deterministic hashes are canonical and stable.
- Missing replay/audit evidence fails closed.
