DRAFTING AND ADMISSION RULES
------------------------------------------------------------------------------------------------------------------------
May draft changes for:
- prompts, policies, rubrics, configs, retrieval profiles, semantic cache thresholds, rerank profiles, exemplars, reason priors,
  HITL threshold adjustments, tool schema validations, provider lane constraints, sandbox scope defaults, golden set additions.

Must include:
- target surface, problem statement, evidence link, completed eval_record_id, RCA or pattern record, expected effect,
  rollback plan, blast radius, affected tests, owner/signer, TTL/review plan.

Admission decisions:
- ADMIT_TO_GAUNTLET: complete, evidence-linked, bounded, testable, rollback-capable.
- HOLD_FOR_MORE_EVIDENCE: plausible but incomplete.
- REJECT_WEAK_PROPOSAL: opinion, vague, non-actionable, duplicate, unbounded, or unsupported.
- REQUIRE_SME_REVIEW: high-impact policy/safety/regulatory/customer-facing/broad-blast-radius change.

Hard no:
- no eval-less proposal.
- no unclear target surface.
- no missing rollback.
- no vague "improve prompt" proposals without exact diff.
- no direct 6D entry.
- no current-run repair.

TEST REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
Tests must fail if:
- proposal lacks CompletedEvalRecord.
- proposal lacks RCA/pattern link.
- proposal has no exact diff.
- proposal has no rollback plan.
- proposal has no blast radius.
- proposal goes directly to UWG without gauntlet/approval.
- raw telemetry becomes proposed memory/policy directly.
