PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
E4.1 Failure record
- Bind reason_code, parent_packet_id, failed_attempt_id, failed_span_id, error class, local check failure.
- Separate symptom from root cause.

E4.2 Localize
- Identify schema, parse, timeout, transient dependency, tool return, optional missing field, artifact shape, format, citation formatting, receipt defect.
- Mark non-repairable causes: missing authority, critical input, blocked ACL, unsafe content, policy conflict, route mismatch, human approval need.

E4.3 Repair plan
- Choose bounded fix: retry same call, repair JSON/schema, reformat, normalize deterministic serialization, retry transient tool, preserve partial.
- No new route, plan, tool, source, policy, sandbox, credential, or provider.

E4.4 Snapshot guard
- Verify same blueprint_hash, policy_hash, capability_scope_hash, sandbox_envelope_hash,
  prompt_hash, replay_key, snapshot_manifest_hash, source snapshot.
- Verify same agent_id, agent_type, agent_version, agent_profile_hash, validator_id,
  validator_version, provider_lane, tool_registry_digest, model_registry_digest,
  repair_authority_class, allowed_repair_types, max_repair_count, frozen_execution_context_hash,
  resolver_digest.
- Compute heal_resolution_digest from the heal-side L2ResolutionContext (see 04.5a).
  Heal MUST NOT proceed unless heal_resolution_digest == validator_resolution_digest
  bit-for-bit. Mismatch is a fail-closed event with decisive_rule_id =
  VALIDATOR_AGENT_RESOLUTION_MISMATCH and a sealed REJECTED dispatch.

E4.5 Oscillation guard
- Check repeated reason_code, repeated span failure, retry ceiling, cost ceiling, remaining SLO.
- Stop on thrash.

E4.6 Revalidation
- Run repaired packet through E2/E3-compatible checks.

E4.7 Heal receipt
- Seal repair_attempt_id, tactic, delta, counters, skipped alternatives, before/after hashes.

E4.8 Outcome
- PASS returns to E3.
- FAIL goes to E5 as NEEDS_HELP, FAIL_TERMINAL, or REJECTED.

PHASE 3 ALLOWED REPAIRS
------------------------------------------------------------------------------------------------------------------------
Allowed:
- JSON repair where source content is intact
- schema coercion for known deterministic fields
- output reformat
- retry same transient tool call within ceiling
- resume from existing checkpoint
- trim oversized output while preserving required fields
- attach partial output if allowed

Disallowed:
- choosing a different route
- retrieving new evidence without C0 contract
- asking a human directly
- broadening sandbox or credentials
- silently switching provider/model/tool
- silently changing agent identity, agent version, or agent profile
- silently changing validator identity or validator version
- widening capability_scope_hash or sandbox_envelope_hash
- changing provider_lane after E2
- changing tool_registry_digest or model_registry_digest mid-run
- changing repair_authority_class or allowed_repair_types mid-run
- changing resolver_digest (silent resolver substitution)
- falling back to a default agent when the resolver fails
- running heal without an approved_work_order / validation_packet_id
- attempting a repair NOT in allowed_repair_types
- exceeding max_repair_count
- committing state
- inventing missing facts
- treating human text as authority
