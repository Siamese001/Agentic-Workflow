OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement E3 Exec as the only L2 stage that performs work. It runs one bounded attempt inside the frozen room and classifies the result for E4 or E5.

E3 answers one question only:
"What happened when the approved work order ran inside the granted sandbox and capability envelope?"

PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
E3.1 Attempt open
- Increment attempt_count.
- Start spans for attempt, model/tool/script/subprocess/file IO/network/artifact generation.
- Bind attempt to attempt_seed and run-clock offset.

E3.2 Invocation build
- Build exact call from sealed packet only.
- No hidden parameters, opportunistic tools, unapproved retrieval, or authority expansion.

E3.3 Sandbox run
- Execute inside frozen filesystem, network, syscall, memory, credential, timeout, and circuit-breaker envelope.
- Sandbox writes are temporary artifacts only.

E3.4 Telemetry capture
- Capture latency, tokens, cost, memory, stdout, stderr, return code, file touches, network destinations, model/tool/provider.

E3.5 Output capture
- Collect payload, raw result, files, proposed state diff, generated artifacts, partials, quarantined unsafe output.

E3.6 Local checks
- Verify parseability, schema, artifact hashes, output contract, citation IDs where applicable, tool return shape.

E3.7 Result classify
- SUCCESS
- DEGRADED_SUCCESS
- SOFT_REPAIRABLE
- FAIL_TERMINAL
- NEEDS_HELP
- REJECTED

E3.8 Attempt receipt
- Seal attempt receipt with inputs, outputs, counters, traces, environment digest, result class, reason code.

PHASE 3 EXECUTION LANES
------------------------------------------------------------------------------------------------------------------------
READ / ANALYSIS LANE
- Consumes provided evidence or bounded read packet.
- Produces answer, summary, comparison, extraction, or classification.
- No durable mutation.

MODEL LANE
- Sends signed prompt artifact through approved gateway.
- Uses provider-native schema binding where required.
- Captures model receipt and output parse check.

TOOL LANE
- Invokes approved tool with validated args.
- Captures stdout/stderr/return object.
- Blocks unexpected side effects.

ACTION LANE
- Performs approved reversible/scoped action only.
- Irreversible or high-impact action must arrive with clearance.
- Mutation remains proposed_state_diff unless external action itself is the approved bounded action.

SCRIPT LANE
- Runs approved script or subprocess under sandbox.
- Shell=false where applicable.
- Timeout required.
- Captures exact command, cwd, env allowlist, stdout, stderr, return code, touched files.

ARTIFACT LANE
- Generates tracked file/report/chart/patch/draft/code bundle.
- Attaches artifact_hash, path, manifest, provenance.
