GAP-CLOSED FULL OVERWRITE | MECE | IMPLEMENTATION-GRADE | WINDSURF-EXECUTABLE
========================================================================================================================

PURPOSE
------------------------------------------------------------------------------------------------------------------------
Define the L2 parent glue that wires E1 Prep -> E2 Valid -> E3 Exec -> E4 Heal loop -> E5 Seal while preserving one-packet authority, retry ceilings, repair ceilings, replay integrity, and no durable writes.

SOURCE ALIGNMENT
------------------------------------------------------------------------------------------------------------------------
This file closes the April 2026 gap review without moving ownership across boundaries.
It is additive to the existing MECE split and does not make this folder the owner of upstream or downstream decisions.

GLOBAL NO-OVERLAP LOCK
------------------------------------------------------------------------------------------------------------------------
- U0 / Intake owns request envelope validation and request identity stamping.
- L1 owns intent interpretation, task_spec, query_spec, ambiguity register, and plan recommendation.
- L0 owns route selection and RouteContract authority.
- L3 owns managed workflow shaping, readiness, checkpointing, and step handoff when the route is workflow-managed.
- 03A C0 owns retrieval, evidence shaping, verification, support score, and FinalEvidenceContract.
- 03B Prompt Assembly owns signed provider-ready PromptEnvelope / CompiledPromptArtifact construction.
- L2 owns bounded execution of exactly one approved packet or current L3 step, including local validation, execution, repair, seal, and receipts.
- 00C Runtime Gates own reusable current-run gate law, GateVerdict schema, live gate invocation map, and gate observability.
- 05 Exit owns current-run checkout, aggregation, X3 disposition, HITL freeze/review flow, and CommitRequest handoff to UWG.
- 00A L5 owns governance certification evidence and re-clearance evidence, not live dispositions.
- 00B L4/UWG owns durable state and durable write admission.
- 06 L6 owns completed-run evaluation, RCA, proposal drafting, gauntlet proof, and future-run learning attempts only.
- 99 owns end-to-end acceptance proof that the whole chain actually ran and respected boundaries.

FORBIDDEN OUTPUTS FROM THIS FILE
------------------------------------------------------------------------------------------------------------------------
This file must not emit or own final runtime dispositions unless explicitly stated as a Runtime Gate or Exit owner file.
Layer-local receipts may contain recommendation hints, result classes, candidate diffs, or proof statuses, but they may not
silently grant route authority, durable write authority, final egress approval, or future-run learning promotion.

UNIQUE OWNERSHIP SURFACE
------------------------------------------------------------------------------------------------------------------------
This file owns the L2 internal sequencer only. It does not own any individual E-stage implementation detail already owned by
04.2 through 04.6. It owns the state machine that calls those stages, aggregates their receipts, and decides whether the
next L2-local step is E3 retry, E4 repair, E5 seal, or terminal rejection.

STATE MACHINE
------------------------------------------------------------------------------------------------------------------------
Allowed states:
- RECEIVED_PACKET
- PREPARED
- VALIDATED
- EXECUTING
- LOCAL_REPAIR_EVALUATION
- RETRYING_SAME_AUTHORITY
- SEALING_SUCCESS
- SEALING_DEGRADED_SUCCESS
- SEALING_NEEDS_HELP
- SEALING_REJECTED
- SEALED

Allowed transitions:
- RECEIVED_PACKET -> E1_PREP -> PREPARED
- PREPARED -> E2_VALID -> VALIDATED or SEALING_REJECTED
- VALIDATED -> E3_EXEC -> EXECUTING
- EXECUTING -> SUCCESS -> SEALING_SUCCESS
- EXECUTING -> DEGRADED_SUCCESS -> SEALING_DEGRADED_SUCCESS
- EXECUTING -> SOFT_REPAIRABLE -> LOCAL_REPAIR_EVALUATION
- LOCAL_REPAIR_EVALUATION -> E4_HEAL -> RETRYING_SAME_AUTHORITY or SEALING_NEEDS_HELP or SEALING_REJECTED
- RETRYING_SAME_AUTHORITY -> E2_VALID or E3_EXEC according to repair type
- any terminal seal state -> E5_SEAL -> SEALED

Illegal transitions:
- any L2 state -> L0 route selection
- any L2 state -> C0 retrieval unless pre-authorized as the current bounded tool/read action
- any L2 state -> direct HITL request
- any L2 state -> L4 write
- any L2 state -> L6 learning mutation

WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
S0 receive packet
- Accept only one signed packet or one current L3 step contract.
- Reject packets that attempt to carry multiple unrelated jobs into one L2 execution.
- Bind all sequencer state to one route_contract_ref and one replay_key.

S1 call E1 Prep
- E1 must freeze execution context before validation or execution.
- Sequencer refuses to call E2 if E1 did not produce frozen_execution_context.

S2 call E2 Valid
- E2 must return PASS before any model/tool/script/action lane is invoked.
- If E2 fails, sequencer sends rejection to E5 Seal without calling E3.

S3 call E3 Exec
- E3 may run only one bounded attempt.
- Sequencer increments attempt_count before invocation and records attempt span.
- Sequencer blocks attempt_count > max_attempts.

S4 call E4 Heal if needed
- E4 may run only for SOFT_REPAIRABLE or permitted degraded cleanup.
- Sequencer blocks repair_count > max_repair_count.
- Repair may not change policy_hash, blueprint_hash, replay_key, capability_token, sandbox envelope, route, or workflow scope.

S5 call E5 Seal
- Every outcome reaches E5, including validation failure, rejection, timeout, budget exhaustion, needs-help, degraded success, and success.
- Sequencer passes final proposed_state_diff_candidate as inert evidence only.

S6 emit SequencerReceipt
- Receipt must include all child stage receipts and one deterministic digest.
- Receipt must be attached to sealed_l2_artifact lineage.

FAIL-CLOSED CONDITIONS
------------------------------------------------------------------------------------------------------------------------
- Missing policy_hash, blueprint_hash, replay_key, capability_token, or sandbox_envelope.
- E1 missing frozen_execution_context.
- E2 PASS missing before E3.
- Attempt count exceeds ceiling.
- Repair count exceeds ceiling.
- Repair changes authority snapshot.
- Stage receipt missing or unsigned.
- proposed_state_diff attempts direct persistence.
- L2 tries to emit Exit disposition or UWG commit request.

ACCEPTANCE CRITERIA
------------------------------------------------------------------------------------------------------------------------
The sequencer is complete only when one sample packet can be executed through E1->E2->E3->E5 and one repairable packet can
execute E1->E2->E3->E4->E2/E3->E5 with deterministic receipts, no direct write, and identical replay digest on rerun.
