PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
E5.1 Payload package
- Include final answer, generated artifact, tool/model result, proposed action result, rejection, failure, or needs-help record.
- Include partial output only if route contract permits.
- Quarantine unsafe payloads.

E5.2 Evidence package
- Attach evidence refs, source IDs, citation anchors, C0 contract refs, state diff, stdout/stderr summary, partials.
- Preserve contradiction flags, support gaps, caveats, support-score hints.

E5.3 Trace package
- Attach trace_id, span_ids, attempts, repairs, invocation records, lineage root, ancestry.

E5.4 Replay package
- Attach replay_key, input_hash, blueprint_hash, policy_hash, prompt_hash, snapshot manifest, deterministic receipts.

E5.5 Terminal stamp
- Classify SUCCESS, DEGRADED_SUCCESS, FAILURE, NEEDS_HELP, REJECTED.
- Include decisive reason code.

E5.6 Contract check
- Verify required fields exist for Exit, L6, HITL packetization, and UWG candidate handoff.

E5.7 Commit boundary
- Assert no durable write occurred.
- Mutation remains proposed_state_diff only.

E5.8 Dispatch receipt
- If L3 step, return to L3 merge.
- If single-step route, dispatch to Exit.
- If HITL/UWG candidate, package as downstream-review data only.

PHASE 3 TERMINAL CLASS RULES
------------------------------------------------------------------------------------------------------------------------
SUCCESS
- Local contract satisfied. Still requires Exit final review.

DEGRADED_SUCCESS
- Useful partial exists. Caveats and gaps remain explicit.

FAILURE
- Work could not complete under current packet, no policy breach.

NEEDS_HELP
- Requires missing input, new authority, HITL, reroute, or broader workflow decision.

REJECTED
- Rule, safety, sandbox, injection, or authority violation.
