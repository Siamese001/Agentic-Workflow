OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Close the validator↔heal agent-resolution gap by giving L2 a single typed
artifact (L2ResolutionContext) whose deterministic digest must match between
the validator that approves a packet and the heal function that executes the
repair. Mismatch is fail-closed with a sealed REJECTED dispatch.

This file exists because, prior to its authoring, L2 documents enforced
hash-equality of the *governance surface* (blueprint_hash, policy_hash,
capability_token, sandbox_envelope, replay_key) but not of the *resolved
agent identity*. The implementation faithfully mirrored the doc gap.

PHASE 1 DATA CONTRACT — L2ResolutionContext
------------------------------------------------------------------------------------------------------------------------
The L2ResolutionContext is a frozen dataclass. Every field is required (no
optional fields below the line). The canonical-JSON serialization sorts keys
deterministically and is hashed with SHA-256 to produce the resolution digest.

Identity fields:
- request_id                       # opaque request id (frozen at intake)
- run_id                           # L2 run id
- trace_id                         # OTEL trace id (root)
- route_id                         # L0-resolved route id
- step_id                          # nullable; L3 step id when L3-managed

Agent identity fields (the gap closure):
- agent_id                         # resolved agent identity
- agent_type                       # class/role of the resolved agent
- agent_version                    # version string
- agent_profile_hash               # SHA-256 of agent profile

Validator identity fields:
- validator_id                     # validator that approved this packet
- validator_version                # validator version

Authority / capability surface:
- capability_token                 # legacy stable label
- capability_scope_hash            # SHA-256 of resolved permissions snapshot
- sandbox_envelope_hash            # SHA-256 of resolved sandbox envelope
- policy_hash                      # frozen at E1
- blueprint_hash                   # frozen at E1
- replay_key                       # frozen at E1
- snapshot_manifest_hash           # SHA-256 of replay snapshot manifest

Registry surface:
- tool_registry_digest             # digest of tool registry visible at validation
- model_registry_digest            # digest of model registry visible at validation
- provider_lane                    # frozen lane: anthropic|google|qwen_local|deterministic|hitl

Repair authority:
- repair_authority_class           # LOCAL_SAFE_ONLY | ESCALATE_REQUIRED | NONE
- allowed_repair_types             # tuple[str, ...] — intersected with 04.5 taxonomy
- max_repair_count                 # repair ceiling

Frozen-context surface:
- frozen_execution_context_hash    # SHA-256 of E1-frozen context
- resolver_digest                  # digest of the resolver implementation

PHASE 2 DIGEST RULE
------------------------------------------------------------------------------------------------------------------------
- Serialize the L2ResolutionContext as canonical JSON (RFC 8785 / sort_keys=True,
  ensure_ascii=False, separators=(",", ":")).
- Compute SHA-256 over the UTF-8 byte representation.
- The hex digest is the resolution_digest.
- The validator-side digest is named validator_resolution_digest.
- The heal-side digest is named heal_resolution_digest.
- Bit-for-bit equality is the only acceptable comparison. Substring, prefix,
  and field-subset comparisons are FORBIDDEN.

PHASE 3 INVARIANTS
------------------------------------------------------------------------------------------------------------------------
INV-RC-1   For any L2 run that reaches E4 Heal, validator_resolution_digest
           and heal_resolution_digest MUST be identical.
INV-RC-2   The L2ResolutionContext is frozen at E2 and SHALL NOT be mutated
           after validator_resolution_digest is emitted.
INV-RC-3   The heal function SHALL NOT re-resolve the agent independently —
           it MUST consume the same L2ResolutionContext that produced
           validator_resolution_digest, OR produce a fresh context that
           hashes identically.
INV-RC-4   Mismatch SHALL produce a sealed REJECTED dispatch with
           terminal_class = VALIDATOR_AGENT_RESOLUTION_MISMATCH and
           decisive_rule_id = VALIDATOR_AGENT_RESOLUTION_MISMATCH.
INV-RC-5   On mismatch the pipeline SHALL NOT increment repair_count, SHALL
           NOT call any model / tool / agent, and SHALL NOT emit a
           proposed_state_diff.
INV-RC-6   The sealed REJECTED dispatch SHALL include both digests, the
           first mismatched field name, the trace_id, and the replay refs
           sufficient for downstream Exit Eval to reproduce the rejection.
INV-RC-7   provider_lane SHALL NOT be widened by any heal-side fallback.
           A cascade demotion that would change provider_lane is itself a
           mismatch and MUST fail closed.
INV-RC-8   Default-agent fallback (resolver returning a generic shell when
           a specific agent cannot be resolved) is FORBIDDEN. Resolver
           failure SHALL produce a sealed REJECTED at E2.

PHASE 4 OTEL CONTRACT
------------------------------------------------------------------------------------------------------------------------
Spans emitted by L2 in the resolution path:

l2.resolution.validate
  attrs: request_id, run_id, route_id, step_id, trace_id, agent_id, agent_type,
         agent_version, validator_id, validator_version, policy_hash,
         blueprint_hash, replay_key, capability_scope_hash, sandbox_envelope_hash,
         provider_lane, repair_authority_class, validator_resolution_digest

l2.resolution.heal
  attrs: same set as l2.resolution.validate, plus heal_resolution_digest

l2.resolution.compare
  attrs: validator_resolution_digest, heal_resolution_digest, resolution_match,
         first_mismatched_field (empty string when match), trace_id, decision_id

l2.heal.blocked
  attrs: decisive_rule_id (= VALIDATOR_AGENT_RESOLUTION_MISMATCH),
         validator_resolution_digest, heal_resolution_digest, first_mismatched_field,
         trace_id, sealed_artifact_id, terminal_class

l2.heal.executed
  attrs: trace_id, sealed_artifact_id, repair_count, max_repair_count,
         resolution_match=true, terminal_class

PHASE 5 SEALED REJECTION ON MISMATCH
------------------------------------------------------------------------------------------------------------------------
On INV-RC-1 violation, L2 emits a DispatchReceipt carrying:
  - terminal_stamp = VALIDATOR_AGENT_RESOLUTION_MISMATCH
  - decisive_reason = "validator_resolution_digest != heal_resolution_digest"
  - has_commit_payload = false
  - dispatch_target = EXIT_CONTROL
  - user_visible_safe = false
  - downstream_recommendation = "deny"
  - sealed_l2_artifact_id, validator_resolution_digest, heal_resolution_digest,
    first_mismatched_field, trace_id all sealed into the artifact body.

PHASE 6 TEST CONTRACT (mandatory)
------------------------------------------------------------------------------------------------------------------------
Every L2-capable agent SHALL be exercised by a matrix test that asserts the
following columns for each registered agent:

  agent_id, agent_type, route_id, capability_token, policy_hash,
  blueprint_hash, validator_resolution_digest, heal_resolution_digest,
  result, expected_terminal_class, trace_id, sealed_artifact_id

Negative scenarios required (cross-reference 04.5 expanded test list):
  A  validator_agent_mismatch         agent_id differs
  B  policy_hash_mismatch              policy_hash differs
  C  blueprint_hash_mismatch           blueprint_hash differs
  D  sandbox_widening                  sandbox_envelope_hash differs
  E  capability_widening               capability_scope_hash differs
  F  replay_snapshot_mismatch          replay_key / snapshot_manifest_hash differs
  G  default_agent_fallback            resolver returned a generic fallback
  H  direct_heal_without_validation    heal called without validation_packet_id
  I  direct_L4_write_during_heal       heal attempted durable write
  J  inconsistent_agent_specific_behavior  same repair class across all agents fails identically

Each negative scenario MUST assert: no heal executed, repair_count not
incremented, no model/tool/agent invoked, sealed artifact carries
VALIDATOR_AGENT_RESOLUTION_MISMATCH (or scenario-specific terminal class for
H and I), trace_id present.
