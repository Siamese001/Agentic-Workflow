OBJECTIVE
------------------------------------------------------------------------------------------------------------------------
Implement Programmatic Tool Calling as an L2 sandbox execution lane that batches multiple tool operations into one governed script execution while isolating raw tool outputs from the model context.

"Can an approved script execute multiple bounded tool operations inside the L2 sandbox and return only a safe summarized stdout/card plus receipts?"

PHASE 2 PTC FLOW
------------------------------------------------------------------------------------------------------------------------
1. Receive approved PTC work order from E2.
2. Validate script digest, language, imports, IO plan, tool call manifest, and stdout schema.
3. Freeze model context before raw tool execution.
4. Execute script inside L2 sandbox only.
5. Capture every internal tool call as a receipt.
6. Trap raw tool results inside sandbox storage.
7. Return only stdout summary or structured card to model context.
8. Fail closed on untranscripted IO, capability violation, unknown network call, unapproved file touch, or raw-result leakage.
9. Seal PTC receipt into normal E3 attempt receipt and E5 sealed L2 artifact.

PHASE 3 GATES AND HUMAN REVIEW
------------------------------------------------------------------------------------------------------------------------
- Low-confidence script plans may require human review before execution.
- Policy-ambiguous script plans require L5 certification evidence before E2 PASS.
- Human modifications return as data only.
- Modified script must re-enter L5/E2 validation before execution.
- Human approval never grants durable write authority.

PHASE 4 CONTEXT ISOLATION RULES
------------------------------------------------------------------------------------------------------------------------
Raw tool outputs:
- stay in sandbox
- are referenced by receipt IDs
- do not enter L1/L3 reasoning context
- do not enter final user output directly
- do not become prompt instructions

Stdout summary:
- must conform to expected schema
- must be size bounded
- must exclude secrets, PII leakage, unapproved raw rows, unapproved credentials
- must include enough provenance refs for replay and audit
