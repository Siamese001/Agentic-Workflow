PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
E2.1 Signature chain
- Verify packet integrity, issuer, route contract, prompt envelope, policy snapshot, manifest HMAC.
- Confirm no user, retrieved, tool, or human text overwrote authority fields.

E2.2 Capability scope
- Confirm requested model/tool/action/script lane is inside capability_token.
- Deny silent fallback to different provider, model, tool, credential, network path, interpreter, **agent**, **agent version**, or **validator**.
- Resolve agent identity via the canonical L2 resolver (see 04.5a) and emit
  `validator_resolution_digest` from the resulting L2ResolutionContext.
- The resolved agent_id, agent_version, capability_scope_hash, sandbox_envelope_hash,
  provider_lane, and repair_authority_class are sealed into the ApprovedWorkOrder.
  Heal-time agent re-resolution MUST produce the identical digest.

E2.3 Budget scope
- Validate timeout, retry ceiling, repair ceiling, token limit, compute, memory, IO quota, circuit breaker.
- Reject open-ended autonomy.

E2.4 Schema shape
- Validate required fields, input schema, output schema, tool args, artifact contract, terminal classes.
- Confirm serialization is deterministic.

E2.5 Side-effect class
- Classify read-only, sandbox write, external call, proposed mutation, irreversible action, or disallowed action.
- Confirm mutations remain proposed only until Exit/UWG.

E2.6 Safety sanity
- Check ACL, data boundary, policy tags, injection flags, sandbox escape indicators, secret exposure risks.

E2.7 Executability check
- Confirm the step can run as-is without asking humans, rerouting, replanning, broadening scope, or fetching new authority.

E2.8 Validation receipt
- PASS emits ApprovedWorkOrder.
- FAIL emits sealed rejection packet before any work.

PHASE 3 FAIL CONDITIONS
------------------------------------------------------------------------------------------------------------------------
- invalid signature
- action outside capability
- missing sandbox envelope
- malformed tool/script/model args
- high-risk mutation lacks clearance
- prompt/evidence injection breach
- unsupported output contract
- no deterministic replay surface when required
- PTC script hash mismatch
- late model/tool/provider substitution
- agent identity unresolvable (resolver failed to produce a deterministic agent_id)
- default-agent fallback attempted (resolver returned a generic fallback in lieu of a specific agent)
- validator identity / version drift (validator that approves the packet is not the validator the resolver bound)
- repair_authority_class missing or NONE for a packet that requires E4 capability
