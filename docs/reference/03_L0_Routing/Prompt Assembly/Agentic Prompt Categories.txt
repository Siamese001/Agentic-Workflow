====================================================================================================================================================================================================
AUTHORITY SUMMARY
====================================================================================================================================================================================================

ABSOLUTE
  System/state rulebooks, write law, refusal law, safety invariants.

BINDING
  Role fences, signed PromptEnvelope, route contracts, execution step packets, exit dispositions, citation/grounding contracts.

GOVERNED
  Developer/ops instructions, capability books, output schemas, evaluator rubrics, provider selection.

PERMISSIONED
  Tool/model/network/memory/write access envelopes.

INFORMATIONAL
  RAG evidence, graph context, memory reads, traces.

GUIDING
  Exemplars and golden context.

PRIVATE
  Planning, decomposition, orchestration reasoning.

PROPOSED
  Healing, RCA, learning, future-run promotion candidates.

ZERO
  Raw user prompt / intent.


====================================================================================================================================================================================================
MINIMUM SYSTEM-WIDE PASS RULES
====================================================================================================================================================================================================

1. Raw user text never outranks system policy.
2. Retrieved text is evidence, not instruction.
3. Examples guide style and reasoning, never truth or permission.
4. L1 plans but does not route, retrieve, execute, or write.
5. L0 routes but does not perform the work.
6. C0 retrieves and shapes evidence but does not invent facts or policy.
7. Prompt Assembly packages and signs the executable packet but does not retrieve or execute.
8. L3 appears only for managed multi-step workflow needs.
9. L2 executes only the current bounded step.
10. Every tool/model/network call requires a scoped access envelope.
11. Healing proposes or retries only after validation, never bypasses policy.
12. Exit produces explicit disposition for every terminal path.
13. Human review is bounded data and must re-enter clearance.
14. Durable writes happen only through the Universal Write Gateway.
15. L6 observes, evaluates, synthesizes, and proposes for future runs only.
16. Token trimming preserves authority order.
17. Cache reuse is policy-bound and freshness-aware.
18. Provider selection is explicit and audited.
19. Every run has trace, replay, and lineage receipts.
20. Every prompt-like artifact has a named owner, stage, authority level, and allowed effect.


====================================================================================================================================================================================================
FAST DIDACTIC CHECK
====================================================================================================================================================================================================

Ask of every prompt block:

1. Who owns it?
2. Where does it enter?
3. What authority does it have?
4. Can it instruct, inform, guide, execute, write, or only propose?
5. What higher-priority block can override it?
6. What lower-priority block must never override it?
7. Is it source-labeled?
8. Is it replayable?
9. Is it bounded by scope, budget, and policy?
10. Does it mutate current state, future state, or no state at all?

If you cannot answer those ten questions, the prompt category is not production-grade.
