PHASE 2 WORKSTEPS
------------------------------------------------------------------------------------------------------------------------
C0.4.1 Normalize pool inputs
- Accept CandidateEvidencePool and optional GraphExpandedEvidencePool.
- Preserve original candidate IDs.
- Normalize fields into a common ranking record.
- Mark missing anchors, stale versions, and source lineage gaps.

C0.4.2 Dedupe without losing provenance
- Collapse duplicate spans.
- Merge dense/sparse/metadata/cache lane signals into lane_coverage_map.
- Preserve multiple reasons a piece of evidence was found.
- Preserve graph relation refs separately from retrieval lane refs.

C0.4.3 Score ranking dimensions
- support_target_match_score: how directly the evidence answers the target.
- directness_score: direct span vs surrounding context vs inferred background.
- authority_score: source authority class and version quality.
- freshness_score: satisfies freshness_class.
- exactness_score: exact term/symbol/date/path match where required.
- graph_proximity_score: bounded relation distance and relation type priority.
- contradiction_value_score: conflict evidence is valuable, not noise.
- redundancy_penalty: repeated content with no new support.
- acl_risk_penalty: any boundary risk lowers or excludes.

C0.4.4 Stratify
- MUST_USE gets direct, high-authority, cited, support-target-aligned evidence.
- SUPPORTING gets corroborating context.
- CONTRADICTS gets material conflicts even if inconvenient.
- BACKGROUND gets definitions or orientation context.
- EXCLUDED gets reason-coded rejected evidence.

C0.4.5 Prune to budget
- Apply deterministic trim order.
- Never prune all contradiction evidence if material contradiction exists.
- Preserve at least one direct support item where available.
- Preserve source parity for comparisons.
- Emit token_budget_manifest.

C0.4.6 Emit ShapedEvidenceSet
- Hash stable fields.
- Preserve excluded evidence reasons.
- Handoff to C0.5.
