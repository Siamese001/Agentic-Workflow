# d4e7a2 W1/W2 Acceptance Gate

## Bottom line

d4e7a2 should be considered code/scaffold complete, but W1 is not fully accepted until the holdout file passes schema validation and a separate provenance attestation confirms qualified underwriting analyst review.

## Files in this package

| File | Purpose |
|---|---|
| `apps_underwriting_ai/holdout/rationale_judge_holdout.yaml` | Current 100-row holdout dataset supplied for DS-R1/W1 |
| `apps_underwriting_ai/holdout/rationale_judge_holdout_provenance.yaml` | Required provenance/attestation artifact, currently pending human completion |
| `scripts/validate_underwriting_holdout.py` | CLI validator for schema, distribution, PII patterns, provenance, and W2 key gating |
| `tests/apps_underwriting_ai/test_holdout_provenance_gate.py` | Pytest coverage for schema/provenance failure modes |

## Status semantics

| Status | Meaning |
|---|---|
| `W1_SCHEMA_VALID` | YAML structure is valid, but provenance was not required or not checked |
| `W1_PROVENANCE_PENDING` | Holdout schema may be valid, but W1 cannot be marked complete |
| `W1_COMPLETE` | Schema is valid and provenance is `VERIFIED_ANALYST_ATTESTED` |
| `W1_BLOCKED` | Schema failed |

## Required command examples

```bash
python scripts/validate_underwriting_holdout.py \
  --holdout apps_underwriting_ai/holdout/rationale_judge_holdout.yaml \
  --json
```

Expected current result: schema valid with warning `HOLDOUT_GROUND_TRUTH_EQUALS_HUMAN_SCORE`.

```bash
python scripts/validate_underwriting_holdout.py \
  --holdout apps_underwriting_ai/holdout/rationale_judge_holdout.yaml \
  --provenance apps_underwriting_ai/holdout/rationale_judge_holdout_provenance.yaml \
  --require-provenance \
  --json
```

Expected current result: `W1_PROVENANCE_PENDING`, because the provenance file is intentionally not signed.

```bash
python scripts/validate_underwriting_holdout.py \
  --holdout apps_underwriting_ai/holdout/rationale_judge_holdout.yaml \
  --provenance apps_underwriting_ai/holdout/rationale_judge_holdout_provenance.yaml \
  --require-provenance \
  --require-anthropic-key \
  --json
```

Expected result: `W1_PROVENANCE_PENDING` (exit 2) — blocked on analyst attestation only. `ANTHROPIC_API_KEY` is already configured in CI secrets and local `.env`.

## Acceptance rule

Do not represent synthetic, Cascade-authored, or LLM-authored labels as analyst-labeled. If the labels were generated by Cascade or an LLM, preserve this dataset as a demo/synthetic holdout and keep W1 human replacement blocked.

## Current known warning

The supplied holdout sets `ground_truth_score == human_score` for every example. This is allowed for demo/prototype calibration, but the validator emits `HOLDOUT_GROUND_TRUTH_EQUALS_HUMAN_SCORE` because independent adjudicated labels are stronger evidence for judge reliability.
