PHASE 2 MEMORY STATE CLASSIFICATION
------------------------------------------------------------------------------------------------------------------------
Every memory-like payload must be classified as exactly one of:
- RAW_TELEMETRY: completed-run exhaust, traces, spans, tool outputs, provider receipts. Not memory.
- NORMALIZED_EVIDENCE: L6 normalized evidence record. Not memory.
- EVALUATED_SIGNAL: scored, calibrated evidence. Not memory yet.
- LEARNING_PROPOSAL: proposed future-run update. Not memory yet.
- APPROVED_LEARNING: cleared by proving/approval but not yet committed. Not memory yet.
- PROMOTED_MEMORY: committed by UWG into L4. Durable memory.
- RETIRED_MEMORY: previously promoted but no longer active.

Hard rules:
- Raw telemetry is not memory.
- Human preference is not policy.
- L6 proposal is not durable memory.
- Prompt text generated from a failed run is not an approved example.
- Memory promotion requires evaluated evidence and UWGCommitReceipt.
- Current-run paths must not read unpromoted L6 proposals as memory.

PHASE 3 MEMORY READ API REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
Implement read-only APIs or extend existing equivalents:
- get_memory(memory_id, tenant_scope, policy_hash, snapshot_id) -> MemoryRecord
- search_memory(scope, subject_refs, memory_type, tenant_scope, policy_hash) -> list[MemoryRecord]
- get_approved_examples(task_class, route_id, policy_hash) -> list[ApprovedExampleRecord]
- get_rubric(rubric_id, rubric_version, policy_hash) -> RubricRecord
- get_threshold_profile(task_class, route_id, risk_tier, policy_hash) -> ThresholdProfileRecord
- get_feedback_record(feedback_id, tenant_scope, policy_hash) -> FeedbackRecord

Read rules:
- Reads must be tenant scoped.
- Reads must enforce allowed_future_use.
- Reads must not expose raw telemetry as promoted memory.
- Reads must preserve origin, approval, and audit refs.
- Reads must not summarize away lineage.

PHASE 4 PROMOTION ADMISSION REQUIREMENTS
------------------------------------------------------------------------------------------------------------------------
A memory promotion StateDiff must include:
- LearningProposal ref
- L6 evaluation refs
- support/evidence refs
- calibration refs where applicable
- proof/regression refs
- target memory surface
- scope and expiration
- privacy classification
- rollback plan
- audit refs
- UWG validation receipt

Forbidden promotions:
- raw telemetry -> memory
- unevaluated human feedback -> rubric
- failed run artifact -> approved example
- uncalibrated preference -> policy threshold
- PTC stdout summary -> memory without L6 evaluation and UWG approval
- shadow learning artifact -> active memory without promotion receipt

PHASE 5 FAILURE MODES
------------------------------------------------------------------------------------------------------------------------
Fail closed when:
- raw telemetry promotion attempted
- L6 current-run mutation attempted
- LearningProposal lacks eval refs
- approval/proving refs missing for high-impact memory
- tenant scope missing
- privacy scope missing
- feedback allowed_future_use is false
- rubric has stale policy_hash
- memory record lacks audit refs
- source run cannot be replayed when replay is required
- promotion target is a policy or registry but StateDiff points to memory surface
