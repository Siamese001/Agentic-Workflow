OBJECTIVE
========================================================================================================================
Convert a structurally admissible transport envelope into a canonical payload that L1 can parse.

This stage answers:
"Can the request be represented deterministically without changing the user's meaning?"

REQUIRED CHECKS
========================================================================================================================
S1 Required field validation
- Validate structural fields only.
- Missing semantic details are not U0's job unless they are required schema fields.
- Example: missing "recipient" in a natural language email request is L1 ambiguity unless the API envelope requires recipient.

S2 Unknown field handling
- Preserve unknown fields in raw payload ref.
- Do not silently promote unknown fields to authority.
- Drop or quarantine fields that attempt to override system metadata.

S3 Canonical normalization
- Normalize whitespace and encoding deterministically.
- Preserve raw text separately.
- Preserve user-provided constraints as raw user data, not system instructions.
- Do not rewrite intent, summarize, translate, or interpret.

S4 Digest and idempotency
- Compute normalized_request_hash from stable fields only.
- Do not include wall-clock time or mutable session counters in normalized hash.
- Bind hash to tenant/session scope.
- Emit idempotency_key.

S5 Safe attachment/connector manifests
- Represent attachments and connector refs as refs, not loaded content.
- Do not fetch, parse deeply, or retrieve content.
- Attachments become source handles for L1 to mention and L0/C0 to route later.

OUTPUT RULES
========================================================================================================================
PASS:
- Attach NormalizedRequestPayload, RequestSchemaReceipt, RequestDigestManifest, and IntakeIdempotencyReceipt.
- Continue to 01.4.

FAIL:
- Emit RejectedRequest with rejection_stage = SCHEMA_NORMALIZATION.
- Do not call L1.

TEST REQUIREMENTS
========================================================================================================================
Tests must fail if:
- schema-invalid request reaches L1
- normalization changes user meaning
- request hash changes across equivalent canonical payloads
- request hash includes nondeterministic wall-clock data
- user-provided metadata overrides system request_id/session_id
- attachment content is retrieved during schema normalization
- connector refs are dereferenced during intake

ACCEPTANCE CRITERIA
========================================================================================================================
01.3 is complete when every ValidatedRequest has a stable normalized payload and idempotency binding, while semantic meaning
remains untouched for L1.
