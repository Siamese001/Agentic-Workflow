OBJECTIVE
========================================================================================================================
Bind the request to the minimum identity and tenant/session context needed to decide whether it may proceed to L1.

U0 does not prove every downstream permission.
U0 creates a baseline that downstream L1/L0/C0/L5/00C can consume.

REQUIRED CHECKS
========================================================================================================================
I1 Identity classification
- Classify caller identity state.
- Do not invent identity.
- Do not accept conflicting caller IDs without marking conflict.
- Do not expose raw auth secrets downstream.

I2 Tenant binding
- Bind tenant_id when available.
- If tenant is required and missing, reject.
- If anonymous or unknown tenant is allowed for the channel, mark UNKNOWN_ALLOWED and restrict downstream scope.

I3 Session binding
- Assign session_id.
- Bind conversation/run family if available.
- Prevent session collision across tenants.
- Prevent user-supplied session_id from overriding authenticated session mapping.

I4 Quota admission
- Enforce per-channel, per-tenant, and per-caller quota floor.
- Deny obvious quota overrun before L1.
- Emit reason codes for throttled/rejected requests.

I5 Duplicate baseline
- Detect duplicate inbound envelopes when exact request digest is already in-flight.
- Mark duplicate candidate for downstream idempotency.
- Do not execute or deduplicate downstream work here.

OUTPUT RULES
========================================================================================================================
PASS:
- Attach CallerScopeBaseline, TenantSessionBinding, and QuotaBaselineReceipt to intake context.
- Continue to 01.3.

FAIL:
- Emit RejectedRequest with rejection_stage = IDENTITY_TENANT_SESSION_QUOTA.
- No L1 handoff.

========================================================================================================================

- IDENTITY_PROVIDER_UNAVAILABLE_FAIL_CLOSED

TEST REQUIREMENTS
========================================================================================================================
Tests must fail if:
- request proceeds with required tenant missing
- caller-provided tenant overrides authenticated tenant
- session collision across tenants is accepted
- quota failure proceeds to L1
- duplicate request executes two intake handoffs without duplicate marker
- raw credentials are copied into downstream payload

ACCEPTANCE CRITERIA
========================================================================================================================
01.2 is complete when every admitted request has a bounded caller/tenant/session baseline and no request can smuggle a
cross-tenant or quota-bypassing identity into L1.
