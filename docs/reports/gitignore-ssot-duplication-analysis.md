# Gitignore SSOT Duplication Analysis

Analysis of multiple SSOT files for gitignore/exclusion configuration in the repository.

---

## Executive Summary

**Finding:** There are **3 separate SSOT files** for exclusion patterns, creating duplication and synchronization risks.

2. **.pre-commit-config.yaml** (exclude section) - Manual exclude patterns for pre-commit
3. **.gitignore** - Generated file (should be output, not SSOT)

## Issues Identified

### 1. Synchronization Risk
- **Problem:** pre-commit-config.yaml claims to be "Synchronized with .gitignore" but has no automated sync
- **Impact:** Changes to excluded_paths.yaml don't automatically update pre-commit excludes
- **Risk:** Drift between gitignore and pre-commit excludes over time

### 2. Manual Maintenance Burden
- **Problem:** 48 patterns manually maintained in pre-commit-config.yaml
- **Impact:** Developer must remember to update both files when adding exclusions
- **Risk:** Inconsistent exclusions between git and pre-commit

### 3. Pre-commit-Specific Patterns Not in SSOT
- **Problem:** 28 pre-commit-specific patterns not in excluded_paths.yaml
- **Impact:** These patterns are only in pre-commit, not in gitignore
- **Risk:** Artifacts might be committed to git but excluded from pre-commit

### 4. Gitignore-Specific Patterns Not in Pre-commit
- **Problem:** IDE, virtual env, build patterns not in pre-commit excludes
- **Impact:** These files are gitignored but could still trigger pre-commit hooks
- **Risk:** Unnecessary pre-commit runs on excluded files

## Recommendations

### Option 1: Generate Pre-commit Excludes from SSOT (Recommended)

**Approach:**
1. Add pre-commit-specific patterns to excluded_paths.yaml (new category: `precommit_excludes`)
2. Modify `tools/generate/generate_gitignore.py` to also generate pre-commit exclude section
3. Update .pre-commit-config.yaml to use generated exclude from file

**Implementation:**
```yaml

  - "artifacts/adg_ci_lane_gate_result.json"
  - "artifacts/healing/healing_events.jsonl"
  # ... all pre-commit-specific patterns
```
