## SECTION 1 · Executive Summary

- **Dominant recommendation: `None` (deterministic).** Approximately two-thirds of `agentic_core` surfaces are schema / hash / HMAC / registry / ACL / replay / OTEL-presence / invariant checks that must not invoke any LLM. This matches the boundary rules (L0 deterministic RouteContract; L4/UWG commit; runtime gates emit `GateVerdict` only).
- **`Judge` (Qwen 32B vLLM) is the right default for semantic surfaces.** Specifically: groundedness / citation-support / false-confidence detection, trajectory critique, ambiguous-plan quality, output-quality scoring feeding `g22_output_quality`, retrieval-grader / retrieval-reflexion, claim-extraction, and the `trace_grader` dimensions that ADR-036 already declares LLM-backed. Existing wiring in `L2_execution/healers/healing_router.py` already dispatches the MEDIUM tier to Qwen via `AppsQwenGateway` — the audit recommends extending that same backend to Exit-side judges.
- **`Hybrid (Judge + Ensemble)` is rare and reserved for high-impact final-output and durable-mutation readiness gates.** Specifically: Exit X1/X2/X3 aggregation for user-visible output on regulated routes, `UniversalWriteGateway` / `durable_write_gateway` semantic readiness, safety-policy gates with ambiguous-policy edges, privacy / cross-context leakage. Ensemble escalation fires only when Qwen abstains / returns UNKNOWN / confidence below threshold, or when two independently-rubriced judges disagree. Hybrid should not be the default.
- **`Ensemble Only` is confined to L6 shadow evaluation, judge-drift tracking, shadow router classifier, redteam harnesses, and offline calibration.** `L6_observability/shadow_eval/*`, `judge_drift.py`, `shadow_router_classifier.py`, `shadow_observer.py`, and `L5_safety/redteam/*` are the legitimate cases. Ensemble Only must not leak into live Exit or commit paths.
- **Where no LLM should be used:** all of U0 intake, all of L4/UWG commit path (UWG policy-hashes + HMAC + consistency gate), runtime gates G01/G02/G05-G07/G10-G12/G14-G16/G19-G21/G24-G29 (pure schema / HMAC / enum / replay / OTEL-presence), `L0_routing` RouteContract emission + bandit/ensemble/path routers (deterministic routing logic), `L4_state/uwg/durable_write_consistency_gate`, `L5_safety/validators/*` schema checks, all `types/*` / `contracts/*` modules, and all OTEL emitters / seal validators / ledger integrity / HMAC / CID / key-derivation surfaces.
- **Where Qwen 32B vLLM is explicitly justified today:** `L3_orchestration/exit_eval/judges/*` (currently only Anthropic/OpenAI/generic HTTP backends — Qwen backend should become primary and external becomes escalation_only), `L5_safety/eval_spine/judge_backends/*` (currently `anthropic_stub` + `null` — add `qwen_vllm` backend as default), `L5_safety/eval_spine/trace_grader.py` dimensions (`register_dim_scorer` seam), `L1_cognition/reasoning/retrieval_grader.py` + `retrieval_reflexion.py`, `L1_cognition/reasoning/safety_evaluator.py` semantic lane, `L0_routing/c0_retrieval/contradiction_gap.py` + `weak_support_refinement.py`, and upstream scorers feeding runtime gates G03 / G08 / G09 / G13 (semantic lane) / G17 / G18 / G22 / G23.
- **Justified `Hybrid`:** Exit pipeline at `L3_orchestration/exit_eval/pipeline.py` for the X1D/X1E output-quality + groundedness dimensions on user-visible routes; `L2_execution/enforcement/UniversalWriteGateway.py` + `L4_state/uwg/durable_write_gateway.py` for durable-mutation-readiness semantic check; runtime gate G04 (safety policy, ambiguous policy branches); G17 (privacy/cross-context); G23 (security leakage). Ensemble escalation = second Qwen-vLLM run with a distinct rubric, OR external model (Anthropic/OpenAI) only when Qwen abstains.
- **No new multi-agent ensembles, no agent-swarm patterns.** The `L0_routing/reasoning/ensemble_router.py` and `mixture_of_experts.py` perform deterministic routing/gating across known provider adapters and are correctly classified `None` — they are not candidate-generator ensembles.
